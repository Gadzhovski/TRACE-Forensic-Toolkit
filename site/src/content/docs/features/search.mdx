## An index of the evidence's text

**Search index and indicators** is an analysis module: it walks each image once and stores the readable text of every file in a per-case full-text index (SQLite FTS5). Searching is then instant, and works offline on the case alone. Text is extracted on several processes at once, and a run that was stopped -- cancelled, failed or TRACE closed -- **resumes** where it left off.

Text is extracted from:

- **Documents** -- PDF, Word, Excel, PowerPoint and OpenDocument, RTF, HTML, plain text in any common encoding.
- **Mail** -- Outlook PST / OST, EML and mbox, messages and attachments.
- **Archives** -- ZIP, 7z, RAR, TAR and compressed files, member by member, nested to a depth you set.
- **Files inside files** -- what documents embed: a PDF's attachments, OLE packages and objects in Office and RTF documents, OOXML and ODF media. **Listing ▸ Show Embedded Files** lists any document's embedded files like an archive's members.
- **Notepad tabs** -- the replayed text of Windows 11 Notepad's unsaved tabs.
- **Registry hives** -- key names and values.
- **Everything else** -- printable runs of ASCII *and* UTF-16 text, since Windows stores much of its text as UTF-16 -- Greek, Cyrillic, Hebrew, Arabic and other scripts too.
- **Free space and memory files** -- unallocated space, and `pagefile.sys`, `swapfile.sys` and `hiberfil.sys` -- by their own module, **Search free space and memory files**, run after the file index so the files are searchable first. It resumes from its last checkpoint too.
- **File slack** of every live file, as its own item (`<file> [slack]`).
- **Carved files**, under `[carved]/` with the name of the deleted file they came from.

A hit inside an archive or mailbox opens that member directly -- read from the image, never unpacked to disk.

The Listing's find box filters the folder shown as you type; switch it to **Whole image** to find a file by name anywhere on an indexed image.

## Indicators, validated

While indexing, TRACE extracts indicators and **checks** each one -- a pattern alone produces too much noise:

| Indicator | Kept only if |
|:--|:--|
| **E-mail addresses** | well-formed |
| **URLs** | well-formed |
| **Phone numbers** | in international form, 8-15 digits |
| **Card numbers** | the Luhn check passes and the prefix belongs to a card scheme |
| **IBANs** | the country's length is right and the mod-97 check passes |

**Triage ▸ Indicators** lists the values with how often they occur; select one to see every file holding it. The **Findings ▸ Indicators** node gives one entry per kind across the whole case. Which kinds are extracted is a case setting.

<Aside type="tip" title="Keyword lists">
For a fixed list of terms or regular expressions to run across a case -- and record as findings -- use [keyword lists](/features/detection/#keyword-lists), which search this same index.
</Aside>
