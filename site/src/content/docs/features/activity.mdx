## Targeted, not a walk

The activity module does not crawl the disk. It looks up the paths where each operating system keeps its records -- case-insensitively, wherever the system root is -- and reads only those. A full Windows XP image is read in a few seconds. A Linux system on Btrfs is read as it was mounted: `/` from its root subvolume, `/home` and `/var` from theirs, as its own `/etc/fstab` says.

Every record has the same shape: **category, source, time, what happened, subject, user**, details, and the file it came from -- so a single click previews the source artifact and a double-click goes to it.

<Aside type="note" title="What a time means">
Not every time is *when it happened*. Where it is not, the record says so in its **basis**: Shimcache's time is the file's modification time; a ShellBag's is when Explorer rewrote the bag; Prefetch's "first run" is the `.pf` file's creation; a shell history without timestamps has its commands in order, with the file's modification time.
</Aside>

## What is read

| Category | Sources |
|:--|:--|
| **Programs** | Prefetch (Windows XP to 11, compressed included), Amcache, Shimcache, UserAssist, BAM, RunMRU, PowerShell history, transcripts (in any language) and script-block logging (event 4104), Windows Error Reporting crash reports, bash / zsh / fish history |
| **Files and folders** | ShellBags, LNK shortcuts, Jump Lists, RecentDocs, TypedPaths, Open/Save dialog history (ComDlg32), Office recent files, macOS recent items and shared file lists, FSEvents, `recently-used.xbel` |
| **Notes and unsaved text** | Windows 11 Notepad tabs -- the text of unsaved and closed tabs, with their unsaved edits replayed, and searchable |
| **USB devices** | USBSTOR, DeviceClasses, MountPoints2, setupapi logs |
| **Logons** | Windows event logs (logons, sessions; service and machine accounts left out), Linux journal, syslog and auth logs (rotated and compressed copies too), wtmp/utmpx, macOS unified log (logons, sudo, screen locks, USB storage); SSH hosts connected to (`known_hosts`) and keys allowed to log in (`authorized_keys`) |
| **Browsers** | Chrome, Edge, Brave, Vivaldi and other Chromium browsers, Firefox, Safari, Internet Explorer (WebCache and `index.dat`) -- history and downloads (with Chromium's danger rating); for Chromium also cookies (names, never values), form entries, saved logins (site and user name, never the password), top sites, favicons, and Local Storage, Session Storage and IndexedDB -- overwritten and deleted values kept -- for browsers and Electron apps such as Teams, Slack and Discord |
| **Searches** | WordWheelQuery (what was typed into Explorer's search box), search-engine searches from browser history, and what was typed into web forms (Chromium autofill) |
| **Network** | NetworkList profiles, SRUM connectivity, Windows Wi-Fi profiles (the key never copied), the Windows Firewall log, Wi-Fi networks on iOS and Android, NetworkManager connections on Linux (saved passwords never copied) |
| **Usage** | SRUM application, network and energy use; macOS KnowledgeC |
| **Communication** | Skype, iMessage and SMS, WhatsApp (iOS and Android), Android and iOS call logs and contacts, and a Cellebrite UFDR report's chats, messages, calls, e-mail and contacts |
| **Cloud** | OneDrive, Google Drive |
| **Antivirus** | Microsoft Defender detection history, MPLog, and quarantined files (decrypted in memory) |
| **Recycle Bin** | `$I` / `$R` (including deleted `$I` records of an emptied bin) and XP's INFO2 |
| **System** | time zone, installed programs, Windows version, macOS install history, phone accounts and builds; Linux release, host name, time zone, user accounts (and who may use sudo), software installed and removed (dnf, apt, dpkg, yum), and Docker and Podman containers |

A **Windows.old** folder -- the install an upgrade replaced -- is read as a system of its own, its users' registry and logs included, and each of its records says *(Windows.old)*.

Windows Timeline (ActivitiesCache.db), SRUM and WebCache are read from their own databases -- ESE through libesedb, SQLite through TRACE's reader, which applies a write-ahead log's committed frames first.

## Conversations

**Triage ▸ Conversations** gathers every message and call the parsers read -- Skype, iMessage and SMS, WhatsApp, call logs, UFDR chats -- into threads per contact: phone numbers are matched by their last nine digits, address books name the numbers, and calls and transfers join their contact's thread. A thread is drawn as the exchange it was, recovered messages marked; **Export Conversation** writes HTML and CSV (audited with their SHA-256), and **Add to Report** puts the thread in the report.

## Deleted records, recovered

SQLite keeps deleted rows in free pages and freeblocks until they are overwritten. TRACE recovers them -- from freelist pages, freeblocks, the gaps between cells, and a WAL's older frames -- and keeps a candidate only if it decodes as a row of one of the database's own tables **and** exactly fills its cell. Recovered Skype and iMessage messages, Android SMS and Chromium and Firefox history appear as *Deleted … (recovered)*.

## Its own parsers, checked against references

Prefetch's LZXPRESS Huffman compression, EVTX binary XML, shell items and LNK files, Linux journals (including zstd-compressed fields), Android's binary XML (ABX) -- each parser is TRACE's own, and its output is compared in the tests with the values plaso, python-evtx and other references publish for the same files.

## The timeline

The timeline merges eight sources into one list: **file-system times** (`$STANDARD_INFORMATION` and `$FILE_NAME` separately on NTFS; created, modified, accessed and changed on every other file system -- ext, Btrfs, XFS, HFS+, APFS, FAT and exFAT, the last two shown as local time since they store no zone), the **change journal** (`$UsnJrnl`), **user activity**, **photo** EXIF times, **document** metadata times, **carved files**, **Sigma detections** and the case's own **events**. Filter by time range, source, user, folder and text -- or only deleted files, only timestomped ones, or without known-good files -- with a histogram on a square-root scale so quiet days still show. **Add to Report** picks rows for the [report](/features/reports/).

## The Recycle Bin, linked

A Recycle Bin record names its `$R` content file; if that file is deleted too, TRACE links the record to the deleted file's entry, so one click previews what was binned -- even when the bin was emptied.
