## Encrypted volumes, unlocked in place

| Volume | Unlocked with |
|:--|:--|
| **BitLocker** (including BitLocker To Go) | the 48-digit recovery key, the password, or a `.BEK` startup key file |
| **FileVault 2** (Core Storage) | password or recovery key |
| **LUKS1 and LUKS2** | passphrase (PBKDF2 or Argon2) |
| **VeraCrypt and TrueCrypt** (containers, partitions, hidden volumes) | password, and the PIM if one was set |
| **Encrypted APFS** | password or recovery key |
| **Encrypted iOS backups** | the backup password |
| **Encrypted Android `adb backup` files** | the backup password |

An unlocked volume **replaces its partition's file system in place**: bookmarks, findings, the tree and every reader keep working exactly as for an unencrypted disk, and analysis, indexing and carving jobs receive the key too. Keys are held **in memory only**, for the session; the audit trail says *unlocked with a recovery key*, never the key.

**LVM inside LUKS** -- the default encrypted Ubuntu and Fedora install -- opens as its logical volumes once the LUKS volume is unlocked, and is carved inside.

**VeraCrypt and TrueCrypt** volumes have no signature, so TRACE never claims to detect one: any partition (or partition-less image) that nothing else opens offers **Unlock as VeraCrypt / TrueCrypt…** in the tree. Every encryption VeraCrypt offers is read -- AES, Serpent, Twofish, Camellia, Kuznyechik and the ten cascades -- with SHA-512, SHA-256 and BLAKE2s key derivation. Whirlpool, Streebog and keyfiles are not supported, and a failed unlock says so rather than blaming the password.

<Aside type="note">
TRACE detects BitLocker by asking libbde, not by a signature byte -- BitLocker To Go hides behind a FAT32 "discovery volume" that other tools open instead.
</Aside>

## More than partitions

- **Volume Shadow Copies** -- each snapshot of an NTFS volume appears in the tree beside the live volume, browsable like any file system. A bookmark into a snapshot still resolves after the case is reopened. **Compare Shadow Copies…** (right-click a snapshot) lists what was deleted, added, changed or renamed between a snapshot and a later one or the live volume -- a file wiped from the live volume opens whole from the snapshot.
- **LVM** -- each logical volume of a volume group.
- **APFS** -- containers and their volumes, read through libfsapfs (The Sleuth Kit's wheels cannot read APFS), with nanosecond times.
- **XFS** -- read through libfsxfs where The Sleuth Kit cannot.
- **Btrfs** -- Fedora's and openSUSE's default, read by TRACE's own reader: every subvolume and snapshot where it is linked (Fedora's `root`, `home` and `var` side by side), zlib, LZO and zstd compression, sparse files, and a multi-disk volume across its member images. **Deleted files** are recovered from the old copies copy-on-write leaves behind, each one only when every data sector matches the checksum Btrfs stored for it. User activity reads a Btrfs system as it was mounted, from its own `/etc/fstab`.
- **ZFS** -- pools on one disk or several (mirror, raidz and stripe; one missing raidz disk rebuilt), every dataset and snapshot, lz4, gzip, zstd, lzjb and zle compression. Natively encrypted datasets are listed, not read.
- **ReFS 3.x** -- Windows Server's and Dev Drive's file system, which neither The Sleuth Kit nor libyal reads.
- **F2FS** (Android's `/data`), **UBI and UBIFS** (raw NAND dumps, the journal replayed), **JFFS2**, **SquashFS** and **EROFS** (firmware and Android system images), **UDF** (DVD and Blu-ray, bridge discs read as UDF so files over 4 GB are there) and **classic HFS** -- each read by TRACE's own pure-Python reader.
- **NTFS, FAT12/16/32, exFAT, ext2/3/4, HFS+, UFS, ISO 9660** -- through The Sleuth Kit 4.15, including compressed and EFS-encrypted NTFS files.
- **The operating system** on each volume is named and shown by its logo -- in the tree, Image Information, the Case tab and the report -- and the Timeline can be narrowed to the volumes holding chosen systems.
- **RAID and multi-disk volumes** -- Linux md arrays (RAID 0, 1, 4, 5, 6 and 10, every superblock version and layout, one missing member rebuilt), Windows **dynamic disks** (simple, spanned, striped, mirrored and RAID5) and **hardware RAID**, which records nothing on its disks: it is rebuilt from level, disk order and stripe size, which TRACE can find by trying the combinations and keeping the one whose files read whole. **File ▸ Assemble RAID or Multi-Disk Volume**; each member disk stays its own evidence.
- **Lost partitions** -- a file system no partition table points at (a wiped table, a broken extended chain, a deleted GPT entry) is found by searching the gaps between partitions, and opens like any volume.
- **Layered file systems** -- a partition formatted again without wiping keeps both file systems; TRACE opens each.
- **Apple Core Storage** without encryption opens directly.

## Containers

- **Virtual disks** -- VMDK, VHD, VHDX, QCOW2 and Parallels. QCOW2 is read by TRACE's own reader, compressed images and backing files included -- libqcow returns about half of a compressed image's data as zeros. A differencing VHD/VHDX or a VMDK snapshot chains its parents from the same folder by name, since the recorded path is the original machine's; a missing parent is named, not guessed.
- **VirtualBox VDI** -- dynamic and fixed, with snapshot chains found by UUID.
- **Android sparse and super images** -- the logical partitions of a dynamic-partition `super.img` open as volumes.
- **AFF** (v1-v3, single file, AFD folder or AFM) and **compressed raw disks** -- `.dd.gz`, `.xz`, `.zst`, `.bz2`, `.lz4` -- read without unpacking them first.
- **Mac disk images** -- DMG (zlib, bzip2, LZFSE, LZMA, ADC compression), sparseimage and sparsebundle.
- **AFF4** -- read by TRACE's own pure-Python reader (maps, image streams, Snappy, LZ4 and deflate); the disk hashes match the reference implementation's on the AFF4 standard reference images, and the container's recorded stream hashes are re-checked on verification.
- **E01 / Ex01** -- every chunk's checksum is checked as it is hashed, and a set with a segment missing or cut short says where its data ends rather than reading zeros. Split raw (`.000` or `.001`), ISO.
- **A folder of an image's segments** -- `x.E01`, `x.E02`… with the imager's log or a report named after the image -- is added as that one image, not as a folder of files.

## Logical evidence

- **AD1** (FTK Imager) -- read in pure Python, hashed the way FTK Imager hashes it, so the hash matches FTK's own log. Encrypted AD1 is refused with a clear message.
- **L01** -- logical evidence files.
- **ZIP and TAR collections**, and **folders** such as KAPE or Velociraptor output -- symbolic links never followed, and the case notes that a folder's times are the copies' times.
- **iOS backups** -- files at their real phone paths, encrypted backups decrypted on the fly with the password.
- **Android `adb backup` files** -- every version, compressed or not, encrypted ones with the password; any file read without unpacking the whole backup.
- **Cellebrite UFDR reports** -- the phone's files at their paths, with the report's chats, messages, calls, contacts, accounts, web history and locations as user activity.
- A phone's file system inside an extraction tool's own folder is recognised as the phone's.

Logical evidence opens as one file system at offset 0, so every module works on it unchanged (there is no unallocated space to carve).

## Live disks

**File ▸ Add Live Disk** reads an attached disk **without imaging it first** -- for preview and triage. TRACE starts a small read-only helper with administrator rights (one prompt), which opens the device read-only and serves sectors to TRACE over a local connection proven by a one-time token. Background jobs reuse the same helper; they never prompt.

A live disk's hashes are recorded as *what was read, when* -- never as verified, because a disk in use changes. TRACE warns before you open the system disk.

The tree, the disk map and the volume table name every region alike -- `GPT Header`, `Linux Filesystem @ 4096 (Ext4)`, `Unallocated Space @ 34` -- in disk order, with free space measured where it really is rather than over the partition tables.
