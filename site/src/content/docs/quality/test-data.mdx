TRACE is tested on **public** evidence only: forensic test images and real artifact files that their authors published, each downloaded from its publisher and checked against a recorded SHA-256 before use. No private or case evidence is ever used, and none is stored in the repository.

| | Count | Where the list lives |
|:--|:--:|:--|
| Disk images downloaded in CI | 23 | `tools/fetch_test_images.py` |
| Larger images tested locally | 7 | `test_images/README.md` |
| Artifact samples | 176 | `tools/fetch_artifact_samples.py` |
| Real files in the carving corpus | 62 | `tools/carve_corpus.py` |

[How the tests run →](/TRACE-Forensic-Toolkit/quality/testing/)

## Disk images (downloaded in CI)

Sixteen of these have a **manifest**: the tests read the whole file system and require every partition and every entry -- inode, size, deleted state, timestamps and SHA-256 -- to equal the committed record.

| Image | Source | What it is | How the tests use it |
|:--|:--|:--|:--|
| `fat-img-kw.dd` | [DFTT #2](https://dftt.sourceforge.net/test2/index.html) | keyword search on FAT16 | keyword lists checked against the published answer key, including what is correctly *not* found (strings in slack or across files); carving quality |
| `ntfs-img-kw-1.dd` | [DFTT #3](https://dftt.sourceforge.net/test3/index.html) | keyword search on NTFS | manifest; NTFS `$I30` index slack compared with dfir_ntfs's parser |
| `ext3-img-kw-1.dd` | [DFTT #4](https://dftt.sourceforge.net/test4/index.html) | keyword search on ext3 | manifest; packaged-app self-test |
| `daylight.dd` | [DFTT #5](https://dftt.sourceforge.net/test5/index.html) | FAT times across a daylight-saving boundary | manifest; FAT times re-read in a child process under a foreign time zone must not move |
| `6-fat-undel.dd` | [DFTT #6](https://dftt.sourceforge.net/test6/index.html) | deleted files on FAT | manifest; deleted entries and what is left of them; carving of deleted files |
| `7-ntfs-undel.dd` | [DFTT #7](https://dftt.sourceforge.net/test7/index.html) | deleted files on NTFS, and a leap day | manifest; deleted entries and what is left of them (a file in two fragments); `$I30` slack compared with dfir_ntfs; carving |
| `8-jpeg-search.dd` | [DFTT #8](https://dftt.sourceforge.net/test8/index.html) | JPEGs found by content, not extension | the second device of the two-image UI test; file types; hex view; YARA; reports; carving the two deleted JPEGs; disk layout; packaged-app self-test |

| `image.gen1.dmg` | [NPS / Digital Corpora](https://digitalcorpora.org/corpora/drives/) | a journaled HFS+ volume | manifest; Mac disk image reading; packaged-app self-test |

## The carving corpus

`tools/carve_corpus.py` lays **62 real published files** -- 63 counting the program inside a TAR -- out among random filler, with **27 signature decoys** (a format's magic followed by junk), and writes the answer key. All 63 must be carved byte-exact and no decoy may be.

| Source | Formats |
|:--|:--|
| [raw.pixls.us](https://raw.pixls.us/) (CC0) | camera raws: ARW, CR2, CR3, DNG, NEF, ORF, PEF, RAF, RW2 |
| [filesamples.com](https://filesamples.com/) | 3GP, M4A, MKV, ODP, ODS, ODT, Opus, RTF, XLSX |
| [GNU](https://www.gnu.org/) | GZIP, BZIP2, XZ, TAR |
| Pillow, psd-tools, libheif, pi-heif test files | AVIF, PSD, PSB, WebP, HEIC |
| java-libpst, python-docx, python-pptx, EPUB samples, the Chinook database | PST, OST, DOCX, PPTX, EPUB, SQLite |
| python-evtx, regf samples, LNK samples, Python e-mails | EVTX, registry hive, LNK, EML |
| rarfile and py7zr test archives | RAR, 7z |
| PuTTY, SQLite, BusyBox, ripgrep, Maven, Androguard | EXE, DLL, ELF, Mach-O, JAR, APK |
| test-videos.co.uk, Wikimedia, Matroska test files, Google | MP4, WebM, OGG, MKV, WebP |

<Aside type="note" title="Tests that make their own images">
Many more tests build small disk images, archives, databases and documents on the fly -- to test an exact edge case, such as a SQLite record deleted in a known way. Those are generated by the tests themselves and are not listed here.
</Aside>
